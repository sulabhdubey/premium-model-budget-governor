# Independent Validation Packet

Status: protocol ready, not completed results. The published authored pilot is
development evidence, not an independent holdout or human onboarding trial.

## Intake

Ask a consenting volunteer or independent maintainer to choose a non-sensitive
task that the governor's developer has not optimized against. Record a random
task ID, public evidence hashes, required capabilities and the release version.
Keep identities, private paths, recordings and observation notes out of Git.
Reject write/Desktop-only tasks as unsupported, rather than silently changing scope.

Before any run, an independent evaluator freezes the acceptance rubric, critical
failure conditions and acceptable task-specific quality tolerance. Keep the rubric
outside the worker project. Include coding, research, writing, visual and review
work, including tasks that need discovered skills. Selection must include expected
failure cases, not only examples favorable to a smaller catalog.

## Consent And Execution

Observation, recording, publishing sanitized results and model spending are
separate choices. No acceptance checkbox buys a reset or authorizes unlimited use.
Specify an experiment envelope, contingency and timeout. One pending lease at a
time; do not rerun an unknown-spend call or discard a costly failed trial.

Use the same evidence, task, required tools, model, reasoning and output allowance
for direct inherited and focused-profile comparisons. If focused discovery cannot
preserve the required skill workflow, record that limitation as an outcome.
Randomize/counterbalance order in advance, retain cache counters and measure all
stages. Add hybrid arms only when they answer a preregistered question.

## Blinded Evaluation

Give the evaluator outputs labeled A/B with model/profile/cost hidden. Record
correctness, omissions, task completion, interventions and serious failures before
revealing consumption. Use executable checks for code where available, and manual
assessment for claims that tests cannot establish. Do not use the routing model's
self-score as independent grading. Record evaluator identity privately and role
only in public aggregates.

After grading is locked, join receipts with task IDs and use `pm-bg experiment`.
Include each call, preparation, retries and verification, plus latency and cached
tokens. Report sample counts, uncertainty, negative outcomes and scope. Same mean
score is not proof of equivalence; no universal or weekly-limit conversion follows.
Repeated public benchmark tasks may be training-contaminated, not true holdouts.

## Decision

- Any unresolved critical privacy, consent or accounting defect blocks promotion.
- A quality regression blocks an original-quality claim for that task class.
- A no-saving result is published and retains direct inherited discovery as default.
- A promising result supports only its tested scope; no automatic policy promotion.
- Human usability requires actual consenting participants under ONBOARDING_TRIAL.md.

The next action is independent task and volunteer intake, not another replay of
the already optimized development fixtures. No new independent results are claimed
by publishing this protocol.

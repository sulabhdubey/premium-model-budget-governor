# FAQ

## Is this anti-frontier-model?

No. It is pro-frontier-model where frontier intelligence has leverage. The
package tries to keep premium models out of broad reading and repeated logs, then
bring them in for compact judgment.

## Does it make tokens cheaper?

No. It reduces waste by changing when and how premium models are used.

## Can it bypass provider limits?

No. It does not bypass usage limits, rate limits, billing, or access controls.

## Can it guarantee the same quality as premium-only work?

No. The honest claim is narrower: it gives you a reproducible way to reserve
premium judgment for moments where it is more likely to matter.

## Why not always use the best model?

Because premium models can waste most of their budget on low-leverage context:
directory scans, duplicate logs, stale artifacts, generated files, and routine
edits. A smaller model can often prepare a much better decision packet.

## What is Sol-parity?

Sol-parity is the ceiling that says a premium capsule should use no more than a
configured fraction of the equivalent Sol workflow. The default rule is:

```text
premium billable token volume <= 40% of equivalent Sol workflow
```

## What is Astra Shadow Mode?

Shadow Mode means the cheaper model does the work first. The premium model sees
only the final answer plus a small evidence capsule and returns approve, reject,
or patch.

## Does the MCP server call model providers?

No. The MCP server exposes routing, scanning, capsule, graph, tournament,
prediction, and telemetry tools. It does not call a model provider.

## Is private project data committed?

No. The repo includes sanitized case studies and example packets. Real project
files, prompts, logs, tokens, and secrets should stay local.

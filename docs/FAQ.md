# FAQ

## Is this anti-frontier-model?

No. Direct Astra is the primary reference: it can investigate, reason, create and
use supported tools. The aim is less avoidable repetition and overhead, not keeping
Astra out of exploration or restricting it to final judgment.

## Does it make tokens cheaper?

No. Provider prices and limits do not change. The Governor offers controls and
measurements for reducing avoidable work; savings must be established for the
tested workflow, including preparation and verification costs.

## Can it bypass provider limits?

No. It does not bypass usage limits, rate limits, billing, or access controls.

## Can it guarantee the same quality as premium-only work?

No. Compare an optimized workflow with equally focused direct Astra using the same
required capabilities and acceptance criteria. Report worse and missing outcomes,
not only cheaper successes. Development evidence is not universal quality equivalence.

## Why not always use the best model?

You can keep Astra as the substantive model. Remove unnecessary repeated retrieval
and clarify acceptance criteria first. Optional helpers need authorization and
whole-workflow evidence; they are not a prerequisite for using Astra. Less context
is not automatically better if it removes evidence or breaks continuity.

## What is Sol-parity?

It is a legacy comparison estimator using configured token/rate assumptions.
It is not a mandatory ceiling for the Astra-preferred workflow, a provider limit,
or proof of matched quality. Compare whole workflows, not a small premium capsule
against an unnecessarily broad Sol baseline.

## What is Astra Shadow Mode?

Shadow Mode is an optional workflow where a cheaper model works first. Astra sees
only the final answer plus a small evidence capsule and returns approve, reject,
or patch.

It is not the default for expensive tasks. Compare its combined cost and quality
with direct Astra; adding a review can simply increase cost.

## Does the MCP server call model providers?

The MCP server exposes planning, budget, scanning, evidence, comparison and
telemetry tools. These tools do not dispatch model runs. Separately, the CLI and
local Workbench have explicitly approved execution paths through the Codex host.
Connecting MCP alone does not control existing chats or change their active model.

## Is private project data committed?

Public artifacts should contain only reviewed examples and sanitized evidence.
Real project files, prompts, logs, tokens and secrets must stay local. Pattern
scans alone cannot establish that an export is safe: review its contents before
publishing, including screenshots and identifiers that may reveal a project.

## Which license should I use for commercial projects?

This repo uses Apache-2.0. It permits commercial use, modification, distribution,
and private use, while also including an explicit patent license and requiring
preservation of license notices.

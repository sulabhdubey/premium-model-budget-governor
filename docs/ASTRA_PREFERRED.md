# Astra-Preferred Workflows

The new planner reserves substantive Astra participation under a total task
budget. It supports direct Astra implementation as well as planning,
investigation, and review. A prior failed Sol attempt is not required.

```sh
pm-bg plan --input examples/astra_preferred.json
```

The example compares three illustrative workflows. Its selected plan costs
4.13 estimated credits including 0.5 contingency: Luna prepares, Astra plans,
Terra implements, and Sol verifies. Candidate scores are equal illustrative
assessments, not measured quality. Raising Astra-direct's quality assessment
selects that candidate when it fits. Actual cost and quality require evaluation.

Provide complete remaining stages, token estimates (ordinary input, cached input,
output), quality assessment, task ceiling, contingency, and already spent credits.
Do not omit hidden reasoning from billed output, double-count cached subsets,
or assume cache hits. Use an equally focused baseline when comparing savings.

Modes: astra_preferred chooses qualifying Astra workflows; adaptive selects the
highest supplied quality score within budget; economy chooses lowest cost above
the supplied minimum quality. Ties prefer lower cost then stable candidate ID.
The planner does not invent candidate token estimates or model capabilities.

An unaffordable requested Astra route returns needs_replan, never silent Sol
fallback. Unknown/emergency capacity requires explicit approval for Astra. A
positive evidence_ready flag is a host assertion, not a security certificate:
hosts must scan evidence, verify source freshness, preserve needed raw material,
and allow focused follow-up retrieval. More useful context is allowed when budgeted.

## Persistent Budget Protocol

Measure host context before calls, not only user prompt length. For live use set
`require_context_calibration: true` and a conservative observed
`minimum_input_tokens_per_call`. Each stage represents one model call; include
every call. The floor increases uncached estimated input and does not invent
cache hits. See [the measured pilot](EXPERIMENTS.md).

`pm-bg budget --input packet.json --ledger budget.sqlite3` supports:

```json
{"action":"open","task_id":"feature-42","budget_credits":5,"reserve_credits":0.5}
```

```json
{"action":"reserve","task_id":"feature-42","lease_id":"plan-1","model":"gpt-6-astra","estimated_credits":1.5}
```

```json
{"action":"settle","task_id":"feature-42","lease_id":"plan-1","actual_model":"gpt-6-astra","actual_credits":1.4}
```

`status` needs task_id only. `cancel` needs lease_id and
confirmed_not_executed=true. Unknown or interrupted executions retain their
reservations. Retrying a reservation or matching settlement is idempotent;
new calls require new IDs. Atomic SQLite transactions prevent double reservation.
Actual overrun is recorded rather than discarded and blocks further reservations.
Contingency is protected and cannot be silently reassigned.

New budgets default to `max_pending_leases: 1`: settle or safely cancel the
current call before reserving another. Explicitly set a higher positive value
when opening a calibrated concurrent task. This is an immutable task setting.
When settling from measured tokens rather than billed credits, set
`cost_basis: token_rate_estimate`. Legacy `actual` fields then hold a projection,
not a provider bill. Model identity and numeric provenance remain host assertions.

MCP exposes `plan_model_workflow` and `manage_task_budget`. The latter uses
the local ~/.pm-bg/budget.sqlite3 store. It stores IDs, models, and numbers, not
prompts. Use opaque task IDs rather than sensitive descriptions.

## Execution Boundaries

The planner has no model credentials and does not execute calls. The optional
`pm-bg run` adapter explicitly invokes an already authenticated Codex CLI in
read-only mode; see GOVERNED_EXECUTION.md. Other hosts
must honor reservations, cap their requests, supply actual receipts, and stop
on exhausted budgets. A reservation cannot prevent an in-flight provider call
from exceeding its estimate. Unknown telemetry is not zero spend.

No current measurement proves Astra-equivalent quality at Sol-equivalent weekly
usage. The planner's numeric budget is in estimated credit units, not a promise
about subscription percentages. The old `route` command remains a single-call
tool; use `plan` for whole-workflow decisions. The website shows illustrative
whole-workflow candidates generated by the Python planner.

The research and validation roadmap is in ASTRA_CAPABILITY_PLAN.md. MCP runtime
tests exercise tools, while EXPERIMENTS.md separately documents the limited live pilot.

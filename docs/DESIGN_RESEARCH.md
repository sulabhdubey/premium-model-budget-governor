# Landing Page Design Research

Research date: 2026-09-07

The landing page uses a custom visual system rather than copying a template. The
reference review focused on systems that improve clarity, accessibility, and
developer-tool credibility.

## Adopted Principles

- [Vercel Geist](https://vercel.com/geist/typography): separate heading, body,
  button, label, and monospace roles so technical UI stays readable.
- [Base UI](https://base-ui.com/): keep controls native, composable, and aligned
  with WCAG 2.2 behavior rather than replacing semantics with decorative divs.
- [Radix Primitives](https://www.radix-ui.com/primitives/docs/overview/introduction):
  preserve keyboard operation, visible focus, and explicit labels for common UI
  patterns.
- [shadcn/ui](https://ui.shadcn.com/docs): favor open code and shared component
  rules that remain easy for maintainers and coding agents to modify.
- [Tailwind Plus](https://tailwindcss.com/plus): use proven responsive section
  anatomy while avoiding licensed component code in this Apache-2.0 project.
- [Landbook](https://land-book.com/): vary section rhythm and density across the
  page instead of repeating a grid of similar cards.

## Project-Specific Translation

The result is an editorial technical page with true-white and cool-gray bands,
graphite typography, teal efficiency signals, amber judgment signals, and coral
only for blocked routes. The interactive demo uses the project's real policy
language and runs entirely in the browser. The generated precision-aperture
visual makes evidence compression legible without moving any functional UI text
into an image.

## Deliberate Exclusions

- No paid template source or redistributed component code.
- No generic pricing, testimonial, logo-cloud, or fake-metric sections.
- No decorative gradients, oversized rounded containers, or nested card grids.
- No React dependency for a static page that needs only native controls and a
  small deterministic simulation.

# Remaining Acceptance Work

The software can be shipped as a testing candidate. The complete product goal
cannot be closed from software tests alone. This register distinguishes actions
from dependencies and prevents a successful single call becoming a savings claim.

## Matched Execution Protocol

Before dispatch, obtain a total experiment credit ceiling distinct from the
previous one-call approval. Use one pending lease at a time, no automatic retries,
no resets, and stop on uncertain spending. Count every stage, failed call and
verification call against the same experiment envelope. Estimates are not hard
provider caps. Do not select a larger envelope by default.

1. Freeze task ID, evidence hashes, exact prompt, quality rubric, host version,
   required tools/images, reasoning effort and model identities before execution.
   Keep grading criteria outside the worker project. Never remove safety rules,
   disable mandatory tools, or change the user's global configuration for a lower
token count.
2. Compare direct Astra, direct Sol, prepared Astra and targeted Astra review on
   equivalent tasks. Do not add a failed Sol run to direct Astra unless that is
   explicitly the workflow being measured. Keep all preparation in the totals.
3. Counterbalance execution order across tasks. Record observed cached tokens;
   do not assume cache hits or label one warm arm a cold comparison. Acknowledge
   host/session differences that cannot be controlled.
4. Use the existing five-task starter suite for coding, research, writing, review
   and visual coverage. A budget that funds only a subset yields a labeled pilot,
   not a complete five-family or four-arm result. No synthetic duplication of
   tasks to inflate sample size.
5. Grade against the frozen criteria, execute bounded code checks when applicable,
   preserve unsuccessful answers privately and publish sanitized negative outcomes.
   Identify Codex grading explicitly. Record complete elapsed time and tokens as
   well as the projected rate-based total.
6. Analyze with the existing experiment/calibration tools. Reject mixed accounting
   bases, incomplete receipts, non-equivalent scope and missing quality labels.
   Do not promote a routing policy without independent calibration and holdout
   evidence meeting the existing reviewed-policy gates.

The 2026-09-07 Astra smoke test is a useful execution baseline, but it was not
counterbalanced and cannot be retroactively converted into a causal experiment.

## Host Context Measurement

Measure the complete input receipt, not just the evidence capsule's text length.
The observed 24,076 tokens are total input, not a proven removable overhead floor.
Separate task text, submitted evidence, actual tool interactions and unclassified
host context where the host exposes those categories. Leave unavailable attribution
unknown. Compare a supported focused session against the same task/required
capabilities before claiming any context reduction. Do not count this parent chat
as free or claim a worker receipt covers all account activity.

## Independent Project Trials

- Private Project A: freeze the current checkpoint/lease renewal question and authoritative
  evidence, verify against the live checkout, and perform a read-only bounded
  review without granting or extending runtime authority.
- Private Project B: freeze current release-authority evidence and review the missing
  gate, without changing releaseAuthorized or treating local tests as launch consent.
- Preserve all existing edits. Public artifacts contain sanitized findings and
  hashes, not private source, personal paths or credentials. Owner-supplied earlier
  reports remain historical context, not new governor-executed trials.

Both need approved, bounded model execution and complete receipts if they are to
count as new governor trials. Static source inspection alone is not equivalent.

## Human And Capability Gates

Follow ONBOARDING_TRIAL.md with one consenting technical and one nontechnical
participant. Record their own explanations, interventions and unsuccessful steps.
Do not send outreach, create identities or claim volunteers participated merely
because the development goal is approved. Automated UI operation remains separate.

Native folder-dialog operation needs an actual user selection on a supported
desktop. Write/Desktop-only capabilities remain explicitly unsupported; extending
them requires a separate consent and threat-model design, not removing the
read-only sandbox. Unavailable provider billing attribution and hard enforcement
cannot be implemented by inventing telemetry or overriding platform safeguards.

## Final Promotion

After the evidence gates pass: resolve observed defects, rerun affected checks,
qualify the exact release artifact, align documentation and landing-page claims,
then promote the release. If a gate fails, publish the limitation and keep testing
status. Prepare outreach using OUTREACH_KIT.md; do not promise virality, universal
savings or unaided nontechnical success before those outcomes are observed.
